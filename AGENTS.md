# Работа над Tracking

## Технические требования

- Целевые сборки — нативные приложения для Windows, Linux, macOS и Android и WebAssembly для браузера. Поддерживайте общий интерфейс egui на desktop и web.
- Используйте стабильный Rust, Cargo Workspace и совместимые версии egui и eframe. eframe управляет рендерингом через wgpu и окнами через winit. Браузерная точка входа собирается для `wasm32-unknown-unknown` через Trunk.
- В desktop-сборке запрещены Electron, Tauri, встроенный WebView, Chromium, Node.js и локальный веб-сервер как зависимость приложения. Интерфейс рисуется средствами egui. HTML браузерной оболочки содержит canvas и загрузку WASM. Интерфейс приложения на HTML/CSS и DOM-фреймворках запрещён. Новый UI-фреймворк требует явного согласования.
- На Android используйте Kotlin и Jetpack Compose. Kotlin вызывает команды `tracking-core` через UniFFI в `apps/android/native`. Храните состояние сессий в SQLite через `tracking-data`.
- Бизнес-логика, состояние и команды принадлежат `tracking-core`. Интерфейс и автоматизация вызывают одни и те же команды. Доступ к часам, хранилищу, сети, файловым диалогам и уведомлениям проходит через платформенные адаптеры. Сводите условную компиляцию к платформенным точкам входа.
- Верстайте экраны под изменение размера и масштаба DPI. Используйте общие цвета, шрифты, размеры и отступы. Длинные списки виртуализируйте там, где это нужно. Обновляйте кадр по событию и планируйте очередное обновление по ближайшему сроку таймера.
- Проверяйте команды и переходы состояния без окна. Используйте тесты egui на desktop и web, инструментальные тесты Compose на Android и проверку отрисованного приложения там, где это практически возможно. При переносе настройте CI для нативных сборок, WASM и границ слоёв.
