# Tracking

Pomodoro-трекер на Rust. Целевой интерфейс — общий egui для нативных
Windows, Linux, macOS и браузера через WebAssembly. Требования к новому стеку
и порядок перехода описаны в [AGENTS.md](AGENTS.md) и
[архитектуре](docs/architecture.md). Возможности продукта описаны отдельно в
[документации трекера](docs/product.md).

## Запуск

Таймер с паузой, автостартом и напоминаниями, история с редактированием и
фильтрами, категории, таймлайн со вложенными зонами и статистика доступны
в одном интерфейсе egui. Активный таймер и история восстанавливаются после
перезапуска.

**Windows, Linux и macOS** с установленным rustup и нативным инструментарием сборки.

```sh
cargo run --locked
```

При необходимости установите зависимости для Linux через
`bash scripts/install-linux-deps.sh`. Приложение открывает тот же локальный SQLite,
что и GPUI-прототип. Для отдельного файла задайте `TRACKING_DB`.

**Браузер** с WebGPU или WebGL2.

```sh
rustup target add wasm32-unknown-unknown
cargo install --locked --version 0.22.2 trunk
cd apps/web
trunk serve --locked
```

Откройте адрес, который выведет Trunk. Браузер сохраняет данные в IndexedDB
отдельно для каждого origin. Эти данные пока не синхронизируются между
сборками.

## Запуск GPUI-прототипа

Существующая сборка использует GPUI и SQLite. Она основана на структуре
[recurring](https://github.com/punkhomov/recurring).

**Windows.** Установите Rust через rustup и Visual Studio Build Tools с рабочей
нагрузкой «Разработка классических приложений на C++». Из корня репозитория
выполните:

```powershell
cargo run --locked -p tracking-app
```

**Linux (Debian, Ubuntu).**

```sh
bash scripts/install-linux-deps.sh
cargo run --locked -p tracking-app
```

Для системного диалога импорта и экспорта на Linux нужен запущенный
`xdg-desktop-portal` с backend для вашего рабочего стола, например
`xdg-desktop-portal-gtk` или `xdg-desktop-portal-kde`.

## Функции GPUI-прототипа

- Таймер работы и перерыва запоминает запущенную сессию и паузу между
  перезапусками. Целевое время, порог паузы, повторные напоминания и автостарт
  настраиваются. Уведомления приходят, пока приложение открыто.
- У сессии могут быть заметка и категория. Историю можно искать, фильтровать,
  дополнять вручную и редактировать. Категории можно архивировать.
- На таймлайне видны сессии и запланированные зоны. Статистика за день, неделю
  и месяц учитывает фактическое время за вычетом засчитанных пауз.
- Путь к SQLite можно переопределить переменной `TRACKING_DB`. По умолчанию база
  создаётся в каталоге локальных данных пользователя.

## Перенос старых данных

В Vue-версии экспортируйте **Все данные**. В Tracking откройте **Настройки**
и нажмите **Импорт JSON**. Поддерживаются старые архивы v1 и архивы Tracking
v2. Перед импортом приложение показывает содержимое файла. По умолчанию
существующие сессии и категории сохраняются. Для замены есть отдельная
опция в окне импорта. Если в файле есть настройки или зоны, они применяются.

В тех же настройках можно экспортировать всё, историю с категориями или
настройки с зонами. На Linux диалоги файлов используют портал рабочего
стола. Для системных уведомлений в браузере разрешите их из настроек
Tracking или через настройки сайта.

## Supabase в GPUI-прототипе

1. Выполните SQL из [миграции](supabase/migrations/20261120000000_tracking_state.sql)
   в SQL Editor нужного проекта или примените миграцию через Supabase CLI.
2. Включите провайдер Email. В шаблонах **Magic Link** и **Confirm signup**
   выведите код, например `<p>Код входа: {{ .Token }}</p>`. Настройте SMTP в
   проекте, если вход должен работать для адресов вне команды Supabase.
3. Скопируйте `.env.example` в `.env` и заполните URL проекта и публичный
   ключ `sb_publishable_…` или legacy `anon`.
4. Запустите `cargo run --locked -p tracking-app` из корня репозитория. В **Настройки → Supabase** введите
   email, запросите код и введите его. Чтобы подключить другое устройство,
   войдите с тем же email.

Сессия входа хранится в памяти до закрытия приложения. После входа обмен
идёт автоматически раз в минуту. Одноимённая кнопка запускает его сразу.
Активный таймер остаётся на том устройстве, где его запустили. История,
категории, зоны и настройки синхронизируются. При изменениях одной записи на
нескольких устройствах Tracking предлагает выбрать, какую версию сохранить.

## Структура

- `crates/core` — таймер, модель сессий, расчёт активного времени и JSON-архив.
- `crates/data` — SQLite, Supabase Auth, синхронизация.
- `crates/ui` и `crates/platform` — экран egui и контракт сохранения.
- `apps/desktop` и `apps/web` — точки запуска eframe.
- `crates/app` — предыдущий GPUI-прототип.

Для будущего Android-клиента `tracking-core` можно подключить к Kotlin через
UniFFI. Интерфейс и работу таймера в фоне реализует Android-клиент.

```sh
cargo fmt --all -- --check
cargo clippy --locked --workspace --all-targets -- -D warnings
cargo test --locked --workspace
```
